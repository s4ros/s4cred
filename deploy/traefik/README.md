# Traefik HTTPS example

Use Traefik v3.7 with its file provider, running on the Compose host. The example listens on `127.0.0.1:443` and does **not** expose the service publicly. Obtain and renew a trusted certificate separately. Replace `notes.example.com` and the certificate paths in `dynamic.yaml`; set the app's `PUBLIC_ORIGIN` to `https://notes.example.com`. Install `traefik.yaml` as `/etc/s4cred/traefik.yaml` and `dynamic.yaml` as `/etc/s4cred/traefik-dynamic.yaml`. Ensure Traefik can read both files and the certificate and private key.

Run `traefik --configFile=/etc/s4cred/traefik.yaml >/dev/null 2>&1` under a service manager with equivalent output suppression. Traefik's access log and tracing are not enabled; general error output is discarded as well because diagnostics may include request details. A logged `/n/{code}` is enough to open an unprotected note. Monitor the process and certificate expiry separately. Do not enable debug logs or have the service manager, CDN, WAF or other intermediaries capture request paths, referers, bodies or tokens.

To expose HTTPS deliberately, change the entrypoint bind address and firewall only after installing the additional controls below, configuring DNS and a valid certificate. There is no port-80 listener or automatic certificate provisioning. If Traefik is containerized or remote, change the upstream to a private reachable app address and secure that network. No Docker socket or Docker provider is needed.

- Buffering rejects request bodies over 1,400,000 bytes. Accepted request bodies are configured to fit in memory; review Traefik's temporary-file behavior and protect temporary storage, as requests may contain read tokens.
- Separate per-IP token-bucket limits are configured for `/api/notes` (10/minute, burst 10) and `/api/notes/` (60/minute, burst 60, all methods). These are starting points, not strict rolling-window counters. HTTP in-flight requests are limited to 20 per source IP, **not TCP connections**. Before public deployment enforce per-IP connection limits at a trusted edge firewall/load balancer, and test HTTP/2 behavior.
- Read, write, idle, upstream dial and response-header timeouts are configured. The read timeout covers the whole request; write timeout includes response time. Tune for legitimate slow clients.
- No retry middleware or buffering retry expression is configured, and idempotency headers are removed. Do not add retries at Traefik, other intermediaries or clients. A failed delivery can still consume a note.
- No upstream proxy is trusted for forwarding headers by default. Traefik replaces its standard untrusted `X-Forwarded-*` values; `Forwarded` and the additional headers listed in the middleware are stripped. Arbitrary vendor-specific forwarding headers are not generically filtered; the app must not trust them. Rate limits use the direct peer address. If behind a load balancer, restrict direct access, configure only its exact trusted CIDRs and the correct client-IP strategy, and ensure it strips client-supplied forwarding headers. Otherwise limits can collapse to the proxy IP or be spoofed. The app itself uses the configured origin, not forwarding headers.
